# Research and operation reminders

These additions extend existing hooks. They do not execute research, load skills, contact providers, approve accounts or delete graphs.

## Explicit research

Start an actual prompt with `::deep-research` and its question. Rules-Check points to the bounded workflow; Skills-Check points to phase-specific research and connected-skill contracts plus current catalogue records. Native `/deep-research` remains native. Ordinary mentions, quoted/inline/fenced examples and pasted output wrappers do not activate the explicit route. Input is bounded to32768 characters; uncertain projection stays silent. Repeated unchanged requests are suppressed per delivery identity/client/project/request; changed requests receive fresh guidance.

Guidance requires one question, finite page/call/time/cost limits, primary bodies, citation trails, independent origins, counterevidence, a claim ledger and honest gaps/stop reasons. A Gemini-backed namesake or extraction reference is not the native command; unavailable capabilities are reported, not simulated. No implicit swarm, paid job, monitor, install or publication.

## Identity and operation boundaries

Companion prose can supply name-only compatibility hints. Installed provider coverage still requires structured kind/client/provider/path/version/hash evidence. Commands, source-only definitions, missing resources and metadata-only changes are not new executable capabilities. Discovery and catalogue limits remain unchanged; partial stays unknown.

Mcp-Usage-Check adds relevant request-scoped advisories:
- **Scrapling/extraction:** permitted static HTTP first; legitimate JS rendering only; owned-session finally-close; HTTP seconds versus browser milliseconds; bounded requests/bodies/robots/rates and small batches; selector/provenance/Unicode fidelity. No CAPTCHA, refusal/paywall/auth/proxy bypass, TLS weakening or private URL escape.
- **Agensi:** matching operator reference; acquisition/trial/cloud/install/update/creator preview can persist/transfer/spend even when free. Separate exact approval and original-ID reconciliation; no paid-content export or account/route fallback.
- **Upwork:** official Upwork and `Upwork-Agent-mcp` (historical `upwork-local`) remain distinct; current schema/account/action evidence. `create_draft` saves a real draft immediately, retry may duplicate, publication is separate. Resolve schema conflicts, respect preview/Connects/budget gates and reconcile unknown outcomes.

- **Fiverr:** selected local workspace, not a live marketplace API. `action_commit` needs fresh trusted human approval and produces `manual_handoff` with `remote_executed:false`; never self-approve or claim remote publication/payment. Reconcile original IDs after unknown outcomes.
- **REA:** bind exact artifact/provider/effects; explicit finite action deadlines plus enforceable outer wall/idle/resource/owned-cleanup controls. Inherited environment/localhost are not a sandbox. Inspect `normalized_result`, `Evidence`/`ev_` identifiers, coverage, unknowns and retained state; static readiness is not runtime parity. No device/runtime experiment or fallback is authorized.
- **Telegram Operator:** exact `telegram-access-audit`, `telegram-backup-restore`, `telegram-bot-reconstruction`, `telegram-chat-migration`, `telegram-format-reconstruction` keys under the actual provider. Actual exposure, selected account, action consent, no-deletion holds and finite export/entity coverage remain separate. No account call is needed to test these reminders.

Configured, exposed, connected, authenticated, executed and verified are different. A connection failure is not absence or authority to bypass. No raw prompt, private account ID or configuration value is stored in reminder state.

## Graph lifecycle

Graph-Update-Check retains its existing freshness/cooldown/own-marker contract. Both stale and partial reminders require a healthy owned baseline until coverage, semantics and endpoints verify. On failure preserve/restore healthy state and recovery evidence. Only after success recycle proven owned obsolete copies, leaving one active verified graph plus compact receipts. Unknown/shared/source/fixture/maintained evidence is untouched; no name glob or permanent deletion. Unavailable Recycle Bin means cleanup blocked. The hook performs no deletion or ownership decision and adds no new directory-name completion gate.

## Verification and limits

Offline Rules/Context/Graph regressions cover actual events, repeat/client/host isolation, near-misses, structured identity and untouched graph-like files. No live provider account operation is tested or authorized by these advisories. Installed rollout and actual runtime checks are separate from source CI. This reminder work does not certify CI-input noninterference or waive any historical carryover gate.

## Ordered scope, release and UI guidance (V66/V67)

Rules/Spec Kit/Feature reminders preserve original request order and stable IDs, resume the earliest actionable unfinished item and reconcile all items at closure. Exact other-project authorization or an English Markdown owner handoff is required; sync groups do not authorize source/staging/runner/provider repair. A fallback recent feature is navigation, not ownership. Task-routed owners must be read in full; a new rule Markdown needs its direct registry entry and completeness check.

Rules-Check routes local actual-value secret custody, complete private exports of all stores and isolated restores without reading or exposing values. Final application builds require approved embedded owner identity **and** genuine verified cryptographic signing; missing identity/key/trust blocks publication/activation. It never creates a certificate or substitutes unsigned output.

Approved initial or later logos belong in supported native resources or packaged in-app assets before signing, not only README. UI work actually invokes a matching design skill and researches useful libraries, using intentional product-specific design rather than generic templates; accessible primitives, native controls and existing design systems remain allowed. These are instructions, not keyword proof of approval, asset correctness, signatures or rendered quality. No new hook/event, logo generation, target-app edit or provider action is implied.
