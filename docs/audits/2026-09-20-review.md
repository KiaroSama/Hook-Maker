# Review contracts: evidence, reservation, capacity and installation

**First obey all applicable user, global, repository, client and installed-hook rules. Do not bypass a hook, fabricate a receipt, erase a live incident, merge unverified code, or alter unrelated work.**

Baseline: `b0d1e030bec815892aacffa174bdfc5025fe2b98`. Prior PRs #2 and #3 were merged before this review. This change preserves their implemented fixes and subsequent description-based skill discovery and Speckit work.

## Confirmed mechanisms and implemented repairs

1. Closing evidence could walk backward past a newer user, empty current answer, malformed event or tool-only answer until an older compliant declaration appeared. An explicitly present but empty `last_assistant_message` also permitted this fallback. The shared extractor now returns UNKNOWN on such boundaries, strictly decodes a bounded UTF-8 tail and distinguishes absence of a direct field from an explicitly unusable value. Claude JSONL and witnessed Codex envelope shapes have positive controls; unknown transcript versions remain unknown rather than guessed.
2. A SubagentStop without `agent_transcript_path` read its parent's `transcript_path`. Both clients document the parent/child distinction. Child evidence now requires its own path or its documented direct last-message field. MCP, Rules and Skills consumers no longer fall back to scanning raw transcript text when the canonical current-message extractor returns UNKNOWN. Declarations quoted in blockquotes, indented code or matching Markdown fences are not a completion declaration. `none - TBD` is not a substantive explanation.
3. Summary check-then-write stamps and secondary advisory singleton stamps were unprotected read/modify/write operations. Summary also evicted live session stamps after twelve sessions and shared a slot between clients. The new shared reservation store serializes validation, suppression and atomic replacement under a stable lock. Actor keys include client/session/subagent; records store hashes and ticks, not prompts or command lines. Timed informational notes expire, persistent receipts do not get evicted to free capacity. Failure to persist does not become a claimed delivery. The installer ships the new shared dependency and tests invoke an actual installed copy.
4. Mutation could publish an oversized/invalid Stop/task document that its next reader rejects. Pending correction receipt/turn collections also silently evicted still-live identity. The actual temporary serialized document is now revalidated before replacement. Active capacities fail explicitly and preserve previous bytes; they do not mint a new task, refund the allowance or silently delete unresolved state.
5. Install results accepted duplicate components and collection-shaped scalar fields. A degraded partial result could be accepted despite a requested client being skipped. Component identities are now unique, the canonical client table is reused, structural scalars/arrays are validated without pipeline unrolling, and partial success requires all requested clients to be actually ok. The producer replaces a component verdict rather than appending duplicates. Before reporting client=ok it independently reads materialized bytes against the intended plan and checks exact registration semantics under the existing resource lock. Native Git is checked against the canonical wrapper/manifest contract; a vanished preserved user hook cannot be silently called healthy.

## Verification and deployment contract

`review-contracts.yml` runs the actual PowerShell on Windows PowerShell 5.1 and PowerShell 7. Each host runs current contracts/integration and an exact-source historical control. Historical control records expected failures separately; an exception or unrelated failure is not a passing red proof. Existing full CI and task/storage regression workflows remain required. New jobs have read-only permissions, immutable action references, bounded children, owned fixture paths, exact source snapshots and result artifacts. Weekly GitHub Actions Dependabot coverage remains applicable; there is no npm/pip dependency ecosystem to invent.

Real installer fault injection is confined to a generated, test-owned source copy. No production fault-injection environment switch is added. Publication fault tests use actual Windows file-sharing failures. Parallel tests execute each actual caller's extracted production function behind a readiness barrier, not a Python translation or a second implementation.

## Important semantics, not renamed promises

A reservation is at-most-once admission, **not exactly-once display**. A crash after reservation but before stdout may omit a reminder. No stdout/file transaction can atomically commit an external UI; do not relabel a reservation as proof the user saw it. Legacy client-less Summary text stamps remain untouched and are not trusted as new client/actor-scoped receipts. An upgrade may emit one new informational reminder. SessionStart deliberately forces re-delivery of starting context; Stop-family Summary output remains silent.

Capacity refusals protect active evidence; this is not a complete terminal-state garbage collector. There is no supported cross-client pre-publication/output-owner integration in these changes. The earlier F01 requirement (exactly one DONE/REMAINING handoff as the final visible output of a live client, including late callbacks) still needs an authorized frontend implementation and event/display trace. Post-response Stop hooks cannot retract already displayed content. No authenticated frontend or private global rules were exercised by these native fixtures.
